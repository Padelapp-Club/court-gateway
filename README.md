# court-gateway

Шлюз, через который партнёры клуба (агрегаторы, приложения для игроков) видят корты, часы
работы, занятость и цены клуба и бронируют корты — поверх CRM клуба.

Шлюз ставится один раз на любой постоянно включённый компьютер клуба или на самую маленькую
облачную машину и **дальше не требует обслуживания**:

- **Никаких открытых портов, белого IP, домена и сертификатов.** Шлюз сам подключается к нашему
  хабу по HTTPS — как браузер открывает сайт. Партнёры ходят в хаб, хаб передаёт запрос шлюзу по
  этому подключению. Пропал интернет, сменился IP, перезагрузили компьютер — шлюз сам вернётся.
- **Обновляется сам.** Раз в сутки шлюз проверяет выпуски, ставит только подписанные нами, а если
  новая версия не заработала — сам возвращает прежнюю.
- **Мы видим, что он работает.** Раз в минуту шлюз сам проверяет вход в CRM и сообщает хабу, что
  жив; если сигнал пропал или шлюз не может войти в CRM, мы узнаем об этом. Вам звонить не нужно —
  мы напишем сами.
- **Ничего не хранит.** Каждый ответ собирается из CRM в момент запроса; базы данных нет.
- **Не отдаёт данные ваших клиентов.** Брони клуба партнёр видит только как «корт занят с … до …»,
  без имён, телефонов и комментариев. Отменить партнёр может только свою бронь.

Поддерживаемые CRM: `viva`. Тип `demo` — учебный, для проверки установки.

## Что понадобится

1. **Компьютер, который всегда включён и подключён к интернету.** Подойдёт ПК на ресепшене
   (Windows 10/11), Mac, мини-ПК с Linux или облачная машина (1 vCPU, до 1 ГБ памяти, Ubuntu).
   Шлюзу хватает десятков мегабайт памяти. Компьютер не должен засыпать.
2. **Логин и пароль администратора Viva** и **идентификатор студии** (UUID из адресной строки
   кабинета Viva).
3. **Код подключения и адрес хаба** — пришлём мы. Код одноразовый и действует сутки.

Если вы ставите шлюз с помощью ИИ-агента (Claude, Codex и подобных) — дайте ему файл
[AGENTS.md](AGENTS.md); от вас агенту понадобятся только пароль Viva и код подключения.

## Установка

Выпуски лежат на странице
<https://github.com/Padelapp-Club/court-gateway/releases/latest>. Там же файл `SHA256SUMS` с
контрольными суммами. Во всех вариантах шаги одинаковые: скачать → `setup` → `install-service` →
`doctor`.

### Windows

1. Создайте папку `C:\court-gateway` и скачайте в неё `court-gateway-<версия>-windows-amd64.exe`,
   переименуйте в `court-gateway.exe`. Если Windows предупредит о неизвестном издателе, нажмите
   «Подробнее» → «Выполнить в любом случае».
2. Откройте **PowerShell от имени администратора** и выполните:

   ```powershell
   cd C:\court-gateway
   # закрыть папку от других пользователей компьютера: в ней будет пароль Viva
   icacls C:\court-gateway /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F"
   .\court-gateway.exe setup
   ```

   Программа спросит адрес хаба, код подключения, логин и пароль Viva, идентификатор студии и
   часовой пояс. Пароль и код при вводе не отображаются.
3. Установите службу — она будет запускаться сама при включении компьютера и перезапускаться при
   сбое:

   ```powershell
   .\court-gateway.exe install-service
   .\court-gateway.exe doctor
   ```

   Журнал службы: `C:\court-gateway\court-gateway.log`.

### macOS

```sh
mkdir -p ~/court-gateway && cd ~/court-gateway
# Apple Silicon (M1–M4): darwin-arm64; Intel: darwin-amd64
curl -fLO https://github.com/Padelapp-Club/court-gateway/releases/latest/download/SHA256SUMS
curl -fLO https://github.com/Padelapp-Club/court-gateway/releases/latest/download/court-gateway-<версия>-darwin-arm64
shasum -a 256 -c --ignore-missing SHA256SUMS
mv court-gateway-*-darwin-arm64 court-gateway && chmod +x court-gateway
./court-gateway setup
sudo ./court-gateway install-service    # служба стартует при включении Mac, работает от вашего имени
./court-gateway doctor
```

Если файл скачан браузером и macOS не даёт его запустить: `xattr -d com.apple.quarantine court-gateway`.
В «Системных настройках → Аккумулятор/Энергосбережение» запретите сон, иначе шлюз будет пропадать.

### Linux (ПК или мини-ПК)

```sh
mkdir -p ~/court-gateway && cd ~/court-gateway
# x86-64: linux-amd64; ARM (Raspberry Pi 4/5 и т. п.): linux-arm64
curl -fLO https://github.com/Padelapp-Club/court-gateway/releases/latest/download/SHA256SUMS
curl -fLO https://github.com/Padelapp-Club/court-gateway/releases/latest/download/court-gateway-<версия>-linux-amd64
sha256sum -c --ignore-missing SHA256SUMS
mv court-gateway-*-linux-amd64 court-gateway && chmod +x court-gateway
./court-gateway setup
sudo ./court-gateway install-service    # systemd; служба работает от вашего пользователя
./court-gateway doctor
```

Журнал: `journalctl -u court-gateway -f`.

### Облачная машина

Создайте самую маленькую машину с Ubuntu (1 vCPU, 512 МБ–1 ГБ). Белый IP и открытые порты не нужны.
Откройте файл [deploy/cloud-init.yaml](deploy/cloud-init.yaml), впишите в него пять значений (адрес
хаба, код подключения, логин, пароль и студию Viva) и вставьте весь текст в поле «Пользовательские
данные» (user data, cloud-init) при создании машины. Через 2–3 минуты шлюз будет на связи; итог
установки — в `/root/court-gateway-setup.json` и `/root/court-gateway-doctor.txt`.

Облако хранит этот текст в настройках машины. Если не хотите передавать пароль так — уберите пароль
и код из файла, а после создания машины зайдите по SSH и выполните
`sudo /opt/court-gateway/court-gateway setup --config /opt/court-gateway/gateway.yaml`.

### Docker

```sh
docker build -t court-gateway:local .     # или готовый образ, когда он будет опубликован
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/config" court-gateway:local setup --config /config/gateway.yaml
docker compose up -d                       # docker-compose.yml из репозитория
docker ps                                  # через минуту статус контейнера — healthy
```

Контейнер не публикует портов. В образе объявлена проверка здоровья
(`/court-gateway healthcheck`): `healthy` — шлюз вошёл в CRM и видит занятость, `unhealthy` — нет
(причина видна в `docker inspect`). Секреты передаются контейнеру переменными окружения из `.env`
(`env_file` в compose), а `gateway.yaml` монтируется только для чтения.

## Проверка: `court-gateway doctor`

```
[ок  ] CONFIG_VALID      клуб my-club, CRM viva, кортов: 4
[ок  ] CRM_LOGIN         вход в CRM выполнен
[ок  ] CRM_OCCUPANCY     занятость на сутки вперёд читается
[ок  ] HUB_REACHABLE     хаб отвечает, сертификат проверен
[ок  ] HUB_AUTH          хаб узнал шлюз клуба my-club
[ок  ] TUNNEL_CONNECTED  служба шлюза на связи с хабом
[ок  ] VERSION_CURRENT   версия 0.1.0 — последняя
Всё в порядке.
```

У каждой ошибки есть подсказка, что сделать. Код выхода не ноль, если есть ошибка. `doctor --json`
выдаёт то же для программ; секреты не печатаются никогда.

## Что собирает `setup` и что проверить

`setup` входит в Viva и составляет черновик `gateway.yaml`:

- **корты** — комнаты Viva, в которых за ближайшие 28 дней есть хотя бы одна бронь. **Корт, на
  котором за это время нет ни одной брони, в черновик не попадёт** — `setup` об этом напомнит;
  допишите такой корт вручную (`id`, `name`, `viva_room`);
- **прайс-листы** — если прайс-лист один, он назначается всем кортам; если их несколько, впишите
  нужный каждому корту (список будет в комментарии в файле);
- **часы работы** — по границам правил прайс-листов по времени;
- **секреты** — пароль Viva и секрет подключения к хабу — в файл `.env` рядом (доступ только
  владельцу), не в `gateway.yaml`.

Всё, что программа могла только угадать, помечено в файле словом «проверьте». После правок
перезапустите службу (`sudo systemctl restart court-gateway`, на Windows — `sc.exe stop
court-gateway` и `sc.exe start court-gateway`, на macOS — `sudo launchctl kickstart -k
system/court-gateway`) и выполните `doctor`.

## Если компьютер выключили или пропал интернет

- Партнёры на это время получают ответ «клуб не на связи» (`503 CLUB_OFFLINE`) и не могут
  бронировать через шлюз. Брони, которые вы заводите в Viva, это не затрагивает.
- Мы получаем уведомление примерно через 3–4 минуты и свяжемся с вами, если это надолго.
- Ничего не теряется: шлюз ничего не хранит. Когда компьютер включат, служба запустится сама и
  через несколько секунд снова будет на связи — делать ничего не нужно.

## Обновления

Шлюз раз в сутки проверяет выпуски (и сразу, если хаб подскажет, что вышла новая версия). Новая
версия ставится, только если: подпись выпуска сошлась с ключом, встроенным в программу; версия
новее текущей; контрольная сумма файла совпала; новая версия прошла самопроверку с вашей
конфигурацией. После перезапуска у новой версии есть 3 минуты, чтобы войти в CRM и подключиться к
хабу, — иначе шлюз вернёт прежнюю версию (она хранится рядом как `court-gateway.prev`).

Выключить автообновление: `update: { enabled: false }` в `gateway.yaml`. Программа, собранная
самостоятельно (без ключа выпусков), не обновляется сама никогда; хаб видит её версию и
предупредит нас, если она устарела.

В Docker обновлённая версия скачивается внутрь контейнера и переживает его перезапуск; если
контейнер пересоздать из образа, шлюз начнёт с версии образа и снова обновится сам.

## Собрать самому и сверить с выпуском

Нужен Go той же версии, что указана в выпуске (сейчас 1.26.4).

```sh
# исходники выпуска — архив «Source code» на странице выпуска
VERSION=<версия> scripts/build.sh     # пять бинарников в dist/ и dist/SHA256SUMS
```

Сборка воспроизводимая: та же версия исходников и Go дают побайтно те же файлы. Чтобы получить
ровно наш выпуск, положите рядом файл `release.pub` со страницы выпуска (открытый ключ выпусков;
без него получится «самосборка» без автообновления) и сравните `dist/SHA256SUMS` с `SHA256SUMS`
выпуска — суммы должны совпасть. `docker build` собирает бинарник с теми же флагами.

## Настройка вручную

Пример со всеми параметрами — [gateway.example.yaml](gateway.example.yaml).

- `club.id` — выдаётся вместе с кодом подключения; `club.name` — название клуба.
- `hub.url` — адрес хаба. Секрет подключения — переменная `GATEWAY_HUB_SECRET` в `.env`.
- `crm` — тип CRM и вход. Пароль — переменная `CRM_PASSWORD` в `.env`.
- `venue` — часовой пояс, шаг сетки (`slot_minutes`), часы работы по дням: `mon` … `sun`,
  диапазоны вида `mon-fri`; выходной — `closed`; конец дня — `24:00`.
- `courts` — корты: `id`, `name`, `viva_room`, необязательно `price_list`.
- `services.booking` / `services.tournament` — услуга Viva для брони партнёра; без раздела бронь
  создаётся технической блокировкой корта.
- `listen` — локальный порт для отладки в своей сети. По умолчанию закрыт; **не пробрасывайте его
  в интернет**. Если он открыт, для запросов к нему нужны ключи в разделе `partners`.
- `update.enabled` — автообновление (по умолчанию включено).

Если в файле ошибка, служба не запустится и перечислит все найденные проблемы.

## API для партнёров

Партнёры обращаются к хабу: `https://<хаб>/v1/clubs/{club}/…`. Все запросы требуют заголовка
`Authorization: Bearer <ключ партнёра>`; ключи и права (`read` — сверка, `book` — ещё и
бронирование) выдаёт оператор хаба. Время — RFC 3339, цены — в целых рублях.

| Запрос | Что делает |
|---|---|
| `GET /v1/clubs` · `GET /v1/clubs/{club}` | клубы партнёра (с признаком `online`) · клуб: часовой пояс, шаг сетки, часы, возможности |
| `GET /v1/clubs/{club}/courts` | корты |
| `GET /v1/clubs/{club}/occupancy?from=&to=[&court=]` | занятость кортов за период |
| `GET /v1/clubs/{club}/prices?court=&date=` | цены корта на дату |
| `GET /v1/clubs/{club}/quote?court=&start=&end=` | стоимость интервала |
| `POST /v1/clubs/{club}/bookings` | создать бронь `{court, start, end, kind: game\|tournament, note}` |
| `GET` · `DELETE /v1/clubs/{club}/bookings/{id}` | прочитать · отменить бронь |
| `POST /v1/clubs/{club}/bookings/{id}/payment` | отметить оплату (если CRM умеет) |

Ошибки: `{"code": "...", "message": "...", "request_id": "..."}`. Кроме ошибок самого API:
`503 CLUB_OFFLINE` — шлюз клуба не на связи; `504 CLUB_TIMEOUT` — шлюз не ответил вовремя.

- **Прошедшие даты.** CRM не отдаёт брони за прошлые дни, поэтому занятость за прошлое приходит с
  пометкой `"complete": false` — это не значит, что корт был свободен.
- **Повтор после таймаута.** Шлюз не хранит запросы и не может распознать повтор. Если ответ на
  создание брони не пришёл, проверьте занятость, прежде чем повторять.
