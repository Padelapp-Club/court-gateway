# court-gateway

Шлюз, через который партнёры клуба (агрегаторы, приложения для игроков) видят корты, часы
работы, занятость и цены клуба и бронируют корты — поверх CRM клуба.

Шлюз ставится один раз на любой постоянно включённый компьютер клуба или на самую маленькую
облачную машину и **дальше не требует обслуживания**:

- **Один код — и всё.** Клуб получает от партнёра один код подключения (например, его показывает
  админ-панель партнёра) и вводит при установке только его и логин с паролем CRM. Идентификатор
  клуба, корты и часы работы клуб не выбирает и не вписывает: их настраивает оператор на хабе.
- **Одна установка — вся сеть клубов.** Если в учётной записи CRM несколько клубов (студий),
  шлюз обслуживает их все. Новый клуб сети оператор подключает на хабе, а шлюз получает его сам:
  на компьютере клуба ничего делать не нужно — ни после установки, ни при добавлении клуба.

- **Никаких открытых портов, белого IP, домена и сертификатов.** Шлюз сам подключается к нашему
  хабу по HTTPS — как браузер открывает сайт. Партнёры ходят в хаб, хаб передаёт запрос шлюзу по
  этому подключению. Пропал интернет, сменился IP, перезагрузили компьютер — шлюз сам вернётся.
- **Обновляется сам.** Раз в сутки шлюз проверяет выпуски, ставит только подписанные нами, а если
  новая версия не заработала — сам возвращает прежнюю. Установленный файл программы при этом не
  меняется, так что даже выключение посреди обновления ничего не ломает.
- **Мы видим, что он работает.** Раз в минуту шлюз сам проверяет вход в CRM и сообщает хабу, что
  жив; если сигнал пропал или шлюз не может войти в CRM, мы узнаем об этом. Вам звонить не нужно —
  мы напишем сами.
- **Ничего не хранит.** Каждый ответ собирается из CRM в момент запроса; базы данных нет.
- **Не отдаёт данные ваших клиентов.** Брони клуба партнёр видит только как «корт занят с … до …»,
  без имён, телефонов и комментариев. Отменить партнёр может только свою бронь.

Поддерживаемые CRM: `viva`. Тип `demo` — учебный, для проверки установки.

## Что понадобится

1. **Компьютер, который всегда включён и подключён к интернету.** Подойдёт ПК на ресепшене
   (Windows 10/11), Mac, мини-ПК с Linux или облачная машина (1 vCPU, до 1 ГБ памяти, Ubuntu).
   Шлюзу хватает десятков мегабайт памяти. Компьютер не должен засыпать.
2. **Логин и пароль администратора Viva.** Идентификатор студии, корты и часы работы не нужны.
3. **Код подключения** — его выдаёт партнёр (например, показывает в своей админ-панели). Код
   одноразовый и действует сутки. Адрес хаба официальная программа знает сама; он нужен, только
   если программа собрана самостоятельно.

Если вы ставите шлюз с помощью ИИ-агента (Claude, Codex и подобных) — дайте ему файл
[AGENTS.md](AGENTS.md); от вас агенту понадобятся только логин и пароль Viva и код подключения.

## Установка

Выпуски лежат на странице
<https://github.com/Padelapp-Club/court-gateway/releases/latest>. Там же файл `SHA256SUMS` с
контрольными суммами. Во всех вариантах шаги одинаковые: скачать → сверить сумму → `setup` →
`install-service` → `doctor`. Команды ниже идут цепочкой: если сумма не сошлась, программа
**не запускается**, и дальше ничего не выполняется.

### Windows

1. Создайте папку `C:\court-gateway` и скачайте в неё со страницы выпуска
   `court-gateway-<версия>-windows-amd64.exe` и `SHA256SUMS`. Если Windows предупредит о
   неизвестном издателе, нажмите «Подробнее» → «Выполнить в любом случае».
2. Откройте **PowerShell от имени администратора** и выполните, вписав версию в строку `$f`:

   ```powershell
   cd C:\court-gateway
   & {
     $f = 'court-gateway-<версия>-windows-amd64.exe'
     $want = (Select-String -Path SHA256SUMS -Pattern (' ' + [regex]::Escape($f) + '$')).Line -split '\s+' | Select-Object -First 1
     if (-not $want -or (Get-FileHash $f -Algorithm SHA256).Hash -ne $want) { throw "Контрольная сумма $f не совпала: не запускайте файл, скачайте его заново" }
     Move-Item -Force $f court-gateway.exe
     .\court-gateway.exe setup --install-service
     .\court-gateway.exe doctor
   }
   ```

   Программа спросит тип CRM, логин и пароль Viva и код подключения — больше ничего (адрес хаба —
   только самостоятельно собранная программа). Пароль и код при вводе не отображаются. Затем она
   закроет папку от других пользователей компьютера (в ней пароль Viva) и установит службу: та
   запускается сама при включении компьютера и перезапускается при сбое.

   Журнал службы: `C:\court-gateway\court-gateway.log`.

### macOS

Впишите в строку `F=` версию и процессор: Apple Silicon (M1–M4) — `darwin-arm64`, Intel —
`darwin-amd64`. `install-service` идёт через `sudo`: служба стартует при включении Mac и работает от
вашего имени.

```sh
F=court-gateway-<версия>-darwin-arm64
B=https://github.com/Padelapp-Club/court-gateway/releases/latest/download
mkdir -p ~/court-gateway && cd ~/court-gateway &&
  curl -fLO "$B/SHA256SUMS" && curl -fLO "$B/$F" &&
  grep " $F\$" SHA256SUMS | shasum -a 256 -c - &&
  mv "$F" court-gateway && chmod +x court-gateway &&
  ./court-gateway setup &&
  sudo ./court-gateway install-service &&
  ./court-gateway doctor
```

Если файл скачан браузером и macOS не даёт его запустить: `xattr -d com.apple.quarantine court-gateway`.
В «Системных настройках → Аккумулятор/Энергосбережение» запретите сон, иначе шлюз будет пропадать.
Журнал службы: `~/court-gateway/court-gateway.log` (сообщения до запуска журнала —
`court-gateway.stderr.log` рядом).

### Linux (ПК или мини-ПК)

Впишите в строку `F=` версию и процессор: x86-64 — `linux-amd64`, ARM (Raspberry Pi 4/5 и т. п.) —
`linux-arm64`. Служба (systemd) работает от вашего пользователя.

```sh
F=court-gateway-<версия>-linux-amd64
B=https://github.com/Padelapp-Club/court-gateway/releases/latest/download
mkdir -p ~/court-gateway && cd ~/court-gateway &&
  curl -fLO "$B/SHA256SUMS" && curl -fLO "$B/$F" &&
  grep " $F\$" SHA256SUMS | sha256sum -c - &&
  mv "$F" court-gateway && chmod +x court-gateway &&
  ./court-gateway setup &&
  sudo ./court-gateway install-service &&
  ./court-gateway doctor
```

Журнал: `journalctl -u court-gateway -f`.

### Облачная машина

Создайте самую маленькую машину с Ubuntu (1 vCPU, 512 МБ–1 ГБ). Белый IP и открытые порты не нужны.
Вставьте весь текст [deploy/cloud-init.yaml](deploy/cloud-init.yaml) в поле «Пользовательские
данные» (user data, cloud-init) при создании машины — он скачает программу, сверит её сумму и
поставит. Через 2–3 минуты зайдите на машину по SSH и выполните:

```sh
sudo -u court-gateway /opt/court-gateway/court-gateway setup --config /opt/court-gateway/gateway.yaml &&
  sudo /opt/court-gateway/court-gateway install-service -config /opt/court-gateway/gateway.yaml --run-as court-gateway
```

**Пароль Viva в пользовательские данные не вписывайте.** Облако хранит их в настройках машины, и
любая программа на машине может прочитать их через сервис метаданных облака всё время её жизни;
файлы на диске скрипт удаляет, а эту копию удалить нельзя. Вписанные в файл пароль и код (так шлюз
ставится без SSH; итог — в `/root/court-gateway-setup.json` и `/root/court-gateway-doctor.txt`)
остаются читаемыми там же.

### Docker

```sh
# образ выпуска (подписанная программа, обновляется сама): впишите его адрес в docker-compose.yml
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/config" <реестр>/court-gateway:<версия> setup --config /config/gateway.yaml
docker compose up -d
docker ps                                  # через минуту статус контейнера — healthy
```

**Пока первый выпуск не опубликован, образа выпуска нет.** До тех пор образ собирается из
исходников (`docker build -t court-gateway:local .` и `image: court-gateway:local` в
`docker-compose.yml`); такой образ — самосборка: он **не обновляется сам**, и адрес хаба `setup`
нужно передать (`--hub-url`).

Контейнер не публикует портов. В образе объявлена проверка здоровья
(`/court-gateway healthcheck`): `healthy` — шлюз вошёл в CRM, его клубы приняты и на связи с хабом;
`unhealthy` — нет (причина видна в `docker inspect`: код CRM, `HUB_AUTH_FAILED` — хаб не принимает
секрет, `HUB_UNREACHABLE` — хаб недоступен дольше 3 минут, `CONFIG_REFUSED` — конфигурация клуба с
хаба не подошла). Секреты передаются контейнеру переменными окружения из `.env`
(`env_file` в compose), а `gateway.yaml` монтируется только для чтения.

## Проверка: `court-gateway doctor`

```
court-gateway 0.2.0 (release)
Установка my-net: конфигурация клубов версии 3 (club-north, club-south); служба применила версию 3 и обслуживает: club-north, club-south
[ок  ] CONFIG_VALID      установка с CRM viva; клубы настраиваются на хабе
[ок  ] CRM_LOGIN         вход в CRM выполнен
[ок  ] CRM_OCCUPANCY     занятость клуба club-north на сутки вперёд читается
[ок  ] HUB_REACHABLE     хаб отвечает, сертификат проверен
[ок  ] HUB_AUTH          хаб узнал шлюз установки my-net
[ок  ] TUNNEL_CONNECTED  служба шлюза на связи с хабом
[ок  ] HUB_CONFIG        конфигурация клубов: версия 3, клубы: club-north, club-south
[ок  ] VERSION_CURRENT   версия 0.2.0 — последняя
Всё в порядке.
```

Сразу после установки, пока оператор ещё не подключил клубы, `CRM_OCCUPANCY` пропускается, а
`HUB_CONFIG` пишет, что клубов пока нет, — это нормально, делать ничего не нужно.

У каждой ошибки есть подсказка, что сделать. Код выхода не ноль, если есть ошибка. `doctor --json`
выдаёт то же для программ; секреты не печатаются никогда.

## Что делает `setup`

`setup` проверяет вход в CRM (неверный пароль не тратит код), обменивает код подключения на
постоянный секрет и записывает:

- `gateway.yaml` — адрес хаба и тип CRM с логином. **Клубов, кортов и часов работы в нём нет**:
  установка — это учётная запись CRM, а её клубы оператор настраивает на хабе;
- `.env` — пароль Viva и секрет подключения к хабу (доступ только владельцу).

Клубы установки оператор настраивает на хабе, шлюз получает их сам и держит только в памяти
([docs/hub.md](docs/hub.md#операторское-api-установки-коды-клубы)). Логин и адреса CRM клуб с хаба
изменить не может: они только в `gateway.yaml` и `.env` на компьютере клуба.

## Если компьютер выключили или пропал интернет

- Партнёры на это время получают ответ «клуб не на связи» (`503 CLUB_OFFLINE`) и не могут
  бронировать через шлюз. Брони, которые вы заводите в Viva, это не затрагивает.
- Мы получаем уведомление примерно через 3–4 минуты и свяжемся с вами, если это надолго.
- Ничего не теряется: шлюз ничего не хранит. Когда компьютер включат, служба запустится сама и
  через несколько секунд снова будет на связи — делать ничего не нужно.

## Обновления

Шлюз раз в сутки проверяет выпуски (и сразу, если хаб подскажет, что вышла новая версия) и ставит
только подписанные нами, прошедшие самопроверку с вашей конфигурацией. Если новая версия за 3
минуты не вошла в CRM и не подключилась к хабу, шлюз сам вернёт прежнюю. Установленный файл
программы при этом не меняется, так что выключение компьютера посреди обновления ничего не ломает
(как это устроено — [docs/hub.md](docs/hub.md#выпуски-и-подписи)). В Docker так же; пересозданный из
образа контейнер начинает с версии образа и снова обновляется сам.

Выключить автообновление: `update: { enabled: false }` в `gateway.yaml`. Программа, собранная
самостоятельно (без ключа выпусков), не обновляется сама никогда; хаб видит её версию и
предупредит нас, если она устарела.

## Собрать самому и сверить с выпуском

Нужен Go той же версии, что указана в выпуске (сейчас 1.26.4). Со страницы выпуска скачайте
архив «Source code», а **вне папки исходников** — открытый ключ выпусков `release.pub` и адрес хаба
`hub-url.txt`:

```sh
cd court-gateway-<версия>      # распакованный «Source code»
RELEASE_KEY_FILE=~/Downloads/release.pub DEFAULT_HUB_URL="$(cat ~/Downloads/hub-url.txt)" \
  VERSION=<версия> scripts/build.sh
# пять бинарников в dist/ и dist/SHA256SUMS — сравните с SHA256SUMS выпуска
```

Сборка воспроизводимая: те же исходники, Go, ключ и адрес хаба дают побайтно те же файлы, поэтому
суммы должны совпасть. Без ключа и адреса (`VERSION=<версия> scripts/build.sh`) получается
самосборка: она не обновляется сама, а `setup` требует `--hub-url`. В репозитории ключа нет, и
сборка его сама не ищет. `docker build` собирает бинарник с теми же флагами
(`--build-arg RELEASE_KEY=… --build-arg DEFAULT_HUB_URL=…`).

## Чего шлюз не видит в Viva

Viva не отдаёт тренировки за прошедшие дни, поэтому шлюз не видит:

- **ночную бронь после полуночи.** Тренировку, начавшуюся вчера, после полуночи прочитать нельзя.
  Интервалы до 04:00 сегодняшнего дня шлюз поэтому не бронирует, но тренировку, которая идёт
  позже 04:00 (например, 23:00–06:00), партнёр в утренние часы увидит свободной;
- **перерыв, начавшийся больше месяца назад.** Многодневные технические перерывы (ремонт) шлюз
  ищет на 31 день назад. Закрываете корт дольше — разбейте перерыв на части не длиннее месяца.

Оператор может изменить эти границы для клуба (см. [docs/hub.md](docs/hub.md#api-для-партнёров)).
