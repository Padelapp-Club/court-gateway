# court-gateway

Шлюз, через который партнёры клуба (агрегаторы, приложения для игроков) видят корты, часы
работы, занятость и цены клуба и бронируют корты — поверх CRM клуба.

Шлюз ставится один раз на любой постоянно включённый компьютер клуба или на самую маленькую
облачную машину и **дальше не требует обслуживания**:

- **Один код — и всё.** При установке клуб вводит только код подключения от партнёра и логин с
  паролем CRM. Клубы, корты и часы работы — в том числе новые клубы сети из той же учётной записи
  CRM — настраивает оператор на хабе, а шлюз получает их сам.

- **Никаких открытых портов, белого IP, домена и сертификатов.** Шлюз сам подключается к нашему
  хабу по HTTPS — как браузер открывает сайт. Партнёры ходят в хаб, хаб передаёт запрос шлюзу по
  этому подключению. Пропал интернет, сменился IP, перезагрузили компьютер — шлюз сам вернётся.
- **Обновляется сам** — только подписанными нами выпусками, с откатом, если новая версия не
  заработала (см. «Обновления»).
- **Мы видим, что он работает.** Раз в минуту шлюз сам проверяет вход в CRM и сообщает хабу, что
  жив; если сигнал пропал или шлюз не может войти в CRM, мы узнаем об этом. Вам звонить не нужно —
  мы напишем сами.
- **Ничего не хранит.** Каждый ответ собирается из CRM в момент запроса; базы данных нет.
- **Не отдаёт данные ваших клиентов.** Брони клуба партнёр видит только как «корт занят с … до …»,
  без имён, телефонов и комментариев. Отменить партнёр может только свою бронь.

Поддерживаемые CRM: `viva`. Тип `demo` — учебный, для проверки установки.

## Что понадобится

1. **Компьютер, который всегда включён и подключён к интернету.** Подойдёт ПК на ресепшене
   (Windows 10/11), Mac, мини-ПК с Linux или облачная машина (1 vCPU, до 1 ГБ памяти, Ubuntu).
   Шлюзу хватает десятков мегабайт памяти. Компьютер не должен засыпать, а часы на нём должны идти
   примерно верно (автоматическое время; ошибку до часа шлюз поправит сам: время броней он берёт с хаба).
2. **Логин и пароль администратора Viva.** Идентификатор студии, корты и часы работы не нужны.
3. **Код подключения** — его выдаёт партнёр (например, показывает в своей админ-панели). Код
   одноразовый и действует сутки. Адрес хаба и его ключ официальная программа знает сама; если
   программа собрана самостоятельно, нужны ещё адрес хаба и отпечаток его ключа (их дают вместе с
   кодом).

Если вы ставите шлюз с помощью ИИ-агента (Claude, Codex и подобных) — дайте ему файл
[AGENTS.md](AGENTS.md); от вас агенту понадобятся только логин и пароль Viva и код подключения.

## Установка

Выпуски лежат на странице
<https://github.com/Padelapp-Club/court-gateway/releases/latest>. Там же файл `SHA256SUMS` с
контрольными суммами. Во всех вариантах шаги одинаковые: скачать → сверить сумму → `setup` →
`install-service` → `doctor`. Команды ниже идут цепочкой: если сумма не сошлась, программа
**не запускается**, и дальше ничего не выполняется.

### Windows

1. Создайте папку `C:\court-gateway` и скачайте в неё со страницы выпуска
   `court-gateway-<версия>-windows-amd64.exe` (Windows на ARM, например на процессоре Snapdragon, —
   `windows-arm64.exe`) и `SHA256SUMS`. Сборка x64 работает и на Windows 11 для ARM через
   эмуляцию, но там лучше родная `arm64`. Если Windows предупредит о неизвестном издателе, нажмите
   «Подробнее» → «Выполнить в любом случае».
2. Откройте **PowerShell от имени администратора** и выполните, вписав в строку `$f` версию (и
   `arm64` вместо `amd64` на ARM):

   ```powershell
   cd C:\court-gateway
   & {
     $f = 'court-gateway-<версия>-windows-amd64.exe'
     $want = (Select-String -Path SHA256SUMS -Pattern (' ' + [regex]::Escape($f) + '$')).Line -split '\s+' | Select-Object -First 1
     if (-not $want -or (Get-FileHash $f -Algorithm SHA256).Hash -ne $want) { throw "Контрольная сумма $f не совпала: не запускайте файл, скачайте его заново" }
     Move-Item -Force $f court-gateway.exe
     .\court-gateway.exe setup --install-service
     .\court-gateway.exe doctor
   }
   ```

   Программа спросит тип CRM, логин и пароль Viva и код подключения — больше ничего (адрес хаба и
   отпечаток его ключа — только самостоятельно собранная программа). Пароль и код при вводе не отображаются. Затем она
   закроет папку от других пользователей компьютера (в ней пароль Viva) и установит службу: та
   запускается сама при включении компьютера и перезапускается при сбое.

   Журнал службы: `C:\court-gateway\court-gateway.log`.

### macOS и Linux

Впишите в строку `F=` версию и платформу: Linux x86-64 — `linux-amd64`, Linux ARM (Raspberry Pi 4/5
и т. п.) — `linux-arm64`, Mac на Apple Silicon (M1–M4) — `darwin-arm64`, Mac на Intel —
`darwin-amd64`. `install-service` через `sudo` ставит системную службу: она стартует при включении
компьютера (на Mac — даже если никто не вошёл) и работает от вашего имени.

```sh
F=court-gateway-<версия>-linux-amd64
B=https://github.com/Padelapp-Club/court-gateway/releases/latest/download
mkdir -p ~/court-gateway && cd ~/court-gateway &&
  curl -fLO "$B/SHA256SUMS" && curl -fLO "$B/$F" &&
  grep " $F\$" SHA256SUMS | if command -v sha256sum >/dev/null; then sha256sum -c -; else shasum -a 256 -c -; fi &&
  mv "$F" court-gateway && chmod +x court-gateway &&
  ./court-gateway setup &&
  sudo ./court-gateway install-service &&
  ./court-gateway doctor
```

Журнал: Linux — `journalctl -u court-gateway -f`, Mac — `~/court-gateway/court-gateway.log`
(до его открытия — `court-gateway.stderr.log`). На Mac запретите сон в настройках энергосбережения;
файл, скачанный браузером, разблокирует `xattr -d com.apple.quarantine court-gateway`; без `sudo`
`install-service` ставит службу пользователя — только для пробы, она работает, пока вы вошли.

### Облачная машина

Создайте самую маленькую машину с Ubuntu (1 vCPU, 512 МБ–1 ГБ). Белый IP и открытые порты не нужны.
Вставьте весь текст [deploy/cloud-init.yaml](deploy/cloud-init.yaml) в поле «Пользовательские
данные» (user data, cloud-init) при создании машины — он скачает программу, сверит её сумму и
поставит. Через 2–3 минуты зайдите на машину по SSH и выполните:

```sh
sudo -u court-gateway /opt/court-gateway/court-gateway setup --config /opt/court-gateway/gateway.yaml &&
  sudo /opt/court-gateway/court-gateway install-service -config /opt/court-gateway/gateway.yaml --run-as court-gateway
```

**Пароль Viva в пользовательские данные не вписывайте:** облако хранит их, и программы на машине
могут их прочитать (почему — в начале [deploy/cloud-init.yaml](deploy/cloud-init.yaml)).

### Docker

```sh
# образ выпуска (подписанная программа, обновляется сама): впишите его адрес в docker-compose.yml
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/config" <реестр>/court-gateway:<версия> setup --config /config/gateway.yaml
docker compose up -d
docker ps                                  # через минуту статус контейнера — healthy
```

**Пока первый выпуск не опубликован, образа выпуска нет.** До тех пор образ собирается из
исходников (`docker build -t court-gateway:local .` и `image: court-gateway:local` в
`docker-compose.yml`); такой образ — самосборка: он **не обновляется сам**, и адрес хаба и
отпечаток его ключа `setup` нужно передать (`--hub-url`, `--hub-key-fingerprint`).

Контейнер не публикует портов. В образе объявлена проверка здоровья
(`/court-gateway healthcheck`): `healthy` — шлюз вошёл в CRM, его клубы приняты и на связи с хабом;
`unhealthy` — нет, код причины виден в `docker inspect` (коды — [docs/hub.md](docs/hub.md#мониторинг)).
Секреты передаются контейнеру переменными окружения из `.env` (`env_file` в compose), а
`gateway.yaml` монтируется только для чтения.

## Проверка: `court-gateway doctor`

```
court-gateway 0.2.0 (release)
Установка my-net: конфигурация клубов версии 3 (club-north, club-south); служба применила версию 3 и обслуживает: club-north, club-south
[ок  ] CONFIG_VALID      установка с CRM viva; клубы настраиваются на хабе
[ок  ] CRM_LOGIN         вход в CRM выполнен
[ок  ] CRM_OCCUPANCY     занятость клуба club-north на сутки вперёд читается
[ок  ] HUB_REACHABLE     хаб отвечает, сертификат проверен
[ок  ] HUB_AUTH          хаб узнал шлюз установки my-net
[ок  ] TUNNEL_CONNECTED  служба шлюза на связи с хабом
[ок  ] HUB_CONFIG        конфигурация клубов: версия 3, клубы: club-north, club-south
[ок  ] VERSION_CURRENT   версия 0.2.0 — последняя
Всё в порядке.
```

Сразу после установки, пока оператор ещё не подключил клубы, `CRM_OCCUPANCY` пропускается, а
`HUB_CONFIG` пишет, что клубов пока нет, — это нормально, делать ничего не нужно.

У каждой ошибки есть подсказка, что сделать. Код выхода не ноль, если есть ошибка. `doctor --json`
выдаёт то же для программ; секреты не печатаются никогда.

## Что делает `setup`

`setup` проверяет вход в CRM (неверный пароль не тратит код), обменивает код подключения на
постоянный секрет и записывает:

- `gateway.yaml` — адрес хаба, установку, открытый ключ хаба (им шлюз проверяет каждый запрос) и
  тип CRM с логином; клубов в нём нет, шлюз получает их с хаба и держит только в памяти. Ключ,
  которым ответил хаб, `setup` сверяет с ключом, встроенным в выпуск, а у самосборки — с
  отпечатком от оператора, а весь ответ хаба — с подписью этого ключа: не совпало —
  `HUB_KEY_MISMATCH`, ничего не записано;
- `.env` — пароль Viva и секрет подключения к хабу (доступ только владельцу).

Логин и адреса CRM хаб изменить не может: они только в этих двух файлах.

## Одна установка — одна копия шлюза

Запускайте шлюз установки только в одном месте. Вторую копию с тем же секретом (скопированная
папка, второй компьютер, Docker рядом со службой) хаб не обслуживает: она пишет в журнал, что
работает другая копия, и ждёт (`DUPLICATE_GATEWAY`), а мы видим это в мониторинге. Если первую
копию выключили или она упала, вторая начинает работать сама, как только у первой закрылись
соединения с хабом: после сбоя или перезапуска — за секунды, после обрыва питания — меньше чем
через минуту; остановленная штатно служба освобождает место сразу.

## Если сменили пароль Viva

Как только Viva отказала шлюзу во входе, он больше не пытается войти, чтобы не заблокировать вашу
учётную запись: партнёры не могут бронировать, а мы получаем тревогу (`CRM_AUTH_FAILED`).
Новый код подключения не нужен. В папке шлюза выполните `court-gateway set-password`
(Windows: `.\court-gateway.exe set-password` в PowerShell от имени администратора): программа
спросит новый пароль, проверит вход в Viva и заменит в `.env` только его. Служба подхватит его сама
в течение минуты — перезапускать её не нужно.

В Docker пароль меняют одноразовым контейнером с папкой настроек, а контейнер шлюза затем
пересоздают: пароль попадает в контейнер переменной окружения при создании, и
`docker compose restart` оставил бы старый.

```sh
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/config" <реестр>/court-gateway:<версия> set-password --config /config/gateway.yaml
docker compose up -d --force-recreate court-gateway
```

## Если в интернет можно только через прокси

Служба не видит переменных прокси из вашей командной строки. Впишите прокси в `gateway.yaml`
(`hub: { proxy_url: http://прокси:3128, no_proxy: "хост, .домен" }`) или в `.env`
(`HTTPS_PROXY=…`, `NO_PROXY=…`): через него пойдут хаб, CRM и проверка выпусков. Для `setup`
задайте те же `HTTPS_PROXY`/`NO_PROXY` в командной строке.

## Удалить службу

`sudo ./court-gateway uninstall-service` (Windows: `.\court-gateway.exe uninstall-service` от имени
администратора), затем удалите папку. На macOS команда снимает и системную службу, и службу
пользователя — какая есть.

## Если компьютер выключили или пропал интернет

- Партнёры на это время получают ответ «клуб не на связи» (`503 CLUB_OFFLINE`) и не могут
  бронировать через шлюз. Брони, которые вы заводите в Viva, это не затрагивает.
- Мы получаем уведомление примерно через 3–4 минуты и свяжемся с вами, если это надолго.
- Ничего не теряется: шлюз ничего не хранит. Когда компьютер включат, служба запустится сама и
  через несколько секунд снова будет на связи — делать ничего не нужно.

## Обновления

Шлюз сам ставит подписанные нами выпуски и сам откатывает версию, которая не заработала;
установленный файл программы при этом не меняется (как это устроено —
[docs/hub.md](docs/hub.md#выпуски-и-подписи)). `court-gateway version` и `doctor` показывают версию,
на которой работает служба.

Выключить автообновление: `update: { enabled: false }` в `gateway.yaml`. Программа, собранная
самостоятельно (без ключа выпусков), не обновляется сама никогда; хаб видит её версию и
предупредит нас, если она устарела.

## Собрать самому и сверить с выпуском

Нужен Go той же версии, что указана в выпуске (сейчас 1.26.4). Со страницы выпуска скачайте
архив «Source code», а **вне папки исходников** — открытый ключ выпусков `release.pub`, адрес хаба
`hub-url.txt` и ключ хаба `hub-key.txt`:

```sh
cd court-gateway-<версия>      # распакованный «Source code»
RELEASE_KEY_FILE=~/Downloads/release.pub DEFAULT_HUB_URL="$(cat ~/Downloads/hub-url.txt)" \
  DEFAULT_HUB_KEY="$(cat ~/Downloads/hub-key.txt)" VERSION=<версия> scripts/build.sh
# шесть бинарников в dist/ и dist/SHA256SUMS — сравните с SHA256SUMS выпуска
```

Сборка воспроизводимая: те же исходники, Go, ключи и адрес хаба дают побайтно те же файлы, поэтому
суммы должны совпасть. Без них (`VERSION=<версия> scripts/build.sh`) получается самосборка: она не
обновляется сама, а `setup` требует `--hub-url` и `--hub-key-fingerprint`. В репозитории ключей
нет, и сборка их сама не ищет. `docker build` собирает бинарник с теми же флагами
(`--build-arg RELEASE_KEY=… --build-arg DEFAULT_HUB_URL=… --build-arg DEFAULT_HUB_KEY=…`).
