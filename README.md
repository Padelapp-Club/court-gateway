# court-gateway

Шлюз, через который партнёры клуба (агрегаторы, приложения для игроков) видят корты, часы
работы, занятость и цены клуба и бронируют корты — поверх CRM клуба.

Шлюз ставится один раз на постоянно включённый компьютер клуба или на самую маленькую облачную
машину и **дальше не требует обслуживания**. При установке клуб вводит только код подключения от
партнёра и логин с паролем CRM; клубы сети, корты и часы работы оператор настраивает на хабе. Шлюз
сам подключается к хабу по HTTPS — открытые порты, белый IP, домен и сертификаты не нужны — и сам
возвращается после обрыва связи или перезагрузки. Он **обновляется сам** только подписанными нами
выпусками, с откатом (см. «Обновления»), и раз в минуту сообщает хабу, что жив и входит в CRM: о
сбое мы узнаем и напишем сами. Шлюз **ничего не хранит** (каждый ответ собирается из CRM в момент
запроса) и **не отдаёт данные ваших клиентов**: брони клуба партнёр видит только как «корт занят с
… до …» и отменить может только свою.

Поддерживаемые CRM: `viva` (вход логином и паролем администратора), `lunda` (Лунда: пароля нет,
шлюз входит сотрудник клуба по QR-коду или коду из сообщения — см. «Лунда: вход сотрудником клуба»)
и `fitness1c` (1С:Фитнес клуб: пользователь 1С и ключ приложения — см. «1С:Фитнес клуб»).

## Что понадобится

1. **Компьютер, который всегда включён и подключён к интернету.** Подойдёт ПК на ресепшене
   (Windows 10/11), Mac, мини-ПК с Linux или облачная машина (1 vCPU, до 1 ГБ памяти, Ubuntu).
   Шлюзу хватает десятков мегабайт памяти. Компьютер не должен засыпать, а часы на нём должны идти
   примерно верно (автоматическое время; ошибку до часа шлюз поправит сам: время броней он берёт с хаба).
2. **Вход в CRM.** Viva — логин и пароль администратора. Лунда — сотрудник клуба с приложением
   Lunda Padel рядом с компьютером при установке (он сканирует QR-код или называет код из
   сообщения) и служебный клиент клуба, на которого встанут брони партнёров. Идентификатор студии,
   корты и часы работы не нужны.
3. **Код подключения** — его выдаёт партнёр (например, показывает в своей админ-панели). Код
   одноразовый; сколько он действует, скажет партнёр. Адрес хаба и его ключ официальная программа знает сама; если
   программа собрана самостоятельно, нужны ещё адрес хаба и отпечаток его ключа (их дают вместе с
   кодом).

Если вы ставите шлюз с помощью ИИ-агента (Claude, Codex и подобных) — дайте ему файл
[AGENTS.md](AGENTS.md); от вас агенту понадобятся только логин и пароль Viva и код подключения (для
Лунды вход вы сделаете сами в терминале — агент подскажет команду).

## Установка

Выпуски лежат на странице
<https://github.com/Padelapp-Club/court-gateway/releases/latest>. Там же файл `SHA256SUMS` с
контрольными суммами и его подпись `SHA256SUMS.sig`; ключ выпусков, которым она сверяется, вписан в
команды ниже, а не берётся со страницы выпуска. Во всех вариантах шаги одинаковые: скачать →
сверить подпись и сумму → `setup` → `install-service` → `doctor`. Команды ниже идут цепочкой: если
подпись или сумма не сошлась, программа **не запускается**, и дальше ничего не выполняется.

### Windows

Откройте **PowerShell от имени администратора**, вставьте команду целиком и выполните, ничего не
меняя. Она сама создаст папку `C:\court-gateway`, скачает в неё последний выпуск для этого
компьютера (x64 или ARM), сверит подпись `SHA256SUMS` ключом выпуска, вписанным в команду, и сумму
программы — и только тогда запустит её. Если что-то не так, команда пишет, что именно, и **ничего
не запускает**. Папку она закрывает от других пользователей до того, как что-либо скачать; если папка
уже есть, открыта и в ней лежат посторонние файлы, команда остановится и скажет, что сделать.

```powershell
& {
  $ProgressPreference = 'SilentlyContinue'
  [Net.ServicePointManager]::SecurityProtocol = 'Tls12'
  $b = 'https://github.com/Padelapp-Club/court-gateway/releases/latest/download'
  $d = 'C:\court-gateway'
  $cpu = if ($env:PROCESSOR_ARCHITEW6432) { $env:PROCESSOR_ARCHITEW6432 } else { $env:PROCESSOR_ARCHITECTURE }
  $a = @{ AMD64 = 'amd64'; ARM64 = 'arm64' }[$cpu]
  if (-not $a) { throw "Процессор $cpu не поддерживается: нужен 64-разрядный Windows (x64 или ARM64)" }
  $ok = 'S-1-5-32-544', 'S-1-5-18', [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
  $closed = {
    $acl = Get-Acl -LiteralPath $d -ErrorAction Stop
    $acl.AreAccessRulesProtected -and $acl.GetOwner([Security.Principal.SecurityIdentifier]).Value -in $ok -and
      -not @($acl.GetAccessRules($true, $true, [Security.Principal.SecurityIdentifier]) | Where-Object { $_.AccessControlType -ne 'Allow' -or $_.IdentityReference.Value -notin $ok[0..1] })
  }
  if (Test-Path -LiteralPath $d) {
    if (((Get-Item -LiteralPath $d -Force -ErrorAction Stop).Attributes -band [IO.FileAttributes]::ReparsePoint) -ne 0) { throw "C:\court-gateway — ссылка на другое место, а не папка. Удалите её и повторите" }
    $extra = @(Get-ChildItem -LiteralPath $d -Force -Name -ErrorAction Stop | Where-Object { $_ -notmatch '^(allowed_signers|(SHA256SUMS(\.sig)?|court-gateway-[0-9][0-9A-Za-z.\-]*-windows-(amd64|arm64)\.exe)(\.txt|\.part)?)$' })
    if ($extra -and -not (& $closed)) { throw "Папка C:\court-gateway уже есть, она открыта другим пользователям, и в ней посторонние файлы ($($extra -join ', ')). Переименуйте её, например в court-gateway.old, и повторите" }
  } else { New-Item -ItemType Directory -Path $d -ErrorAction Stop | Out-Null }
  icacls $d /inheritance:r /grant:r '*S-1-5-32-544:(OI)(CI)F' '*S-1-5-18:(OI)(CI)F' | Out-Null
  if ($LASTEXITCODE -ne 0 -or -not (& $closed)) { throw "Не удалось закрыть папку C:\court-gateway от других пользователей (её владелец — не администратор?). Переименуйте её, например в court-gateway.old, и повторите" }
  Set-Location -LiteralPath $d -ErrorAction Stop
  $drop = { param($p) if (Test-Path -LiteralPath $p) { Remove-Item -LiteralPath $p -Force -ErrorAction Stop } }
  $get = {
    param($n)
    & $drop "$n.part"
    try { Invoke-WebRequest "$b/$n" -OutFile "$n.part" -UseBasicParsing -ErrorAction Stop } catch {
      $e = $_.Exception.Message
      & $drop "$n.part"
      $src = @($n, "$n.txt") | Where-Object { Test-Path -LiteralPath $_ } | Select-Object -First 1
      if (-not $src) { throw "Не удалось скачать $n ($e), и в папке C:\court-gateway его нет. Ничего не запущено" }
      Copy-Item -LiteralPath $src -Destination "$n.part" -ErrorAction Stop
      Write-Host "Не удалось скачать $n ($e) — проверяю копию файла $src из папки"
    }
    Move-Item -LiteralPath "$n.part" -Destination $n -Force -ErrorAction Stop
  }
  & $get SHA256SUMS
  & $get SHA256SUMS.sig
  if (-not (Get-Command ssh-keygen -ErrorAction SilentlyContinue)) { throw "Нет ssh-keygen (OpenSSH) — выполните winget install Microsoft.OpenSSH.Beta, откройте PowerShell от имени администратора заново и повторите" }
  & $drop allowed_signers
  'court-gateway ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIJAe4CDRNNnk++UtmLOdDcQcRc0jK56eYJPo+DfdyK8y' | Set-Content -LiteralPath allowed_signers -Encoding ascii -ErrorAction Stop
  $out = cmd /c 'ssh-keygen -Y verify -f allowed_signers -I court-gateway -n court-gateway -s SHA256SUMS.sig < SHA256SUMS 2>&1'
  if ($LASTEXITCODE -ne 0 -and "$out" -match 'unknown option|illegal option|usage:') { throw "ssh-keygen старше OpenSSH 8.1 и не проверяет подписи — выполните winget install Microsoft.OpenSSH.Beta, откройте PowerShell от имени администратора заново и повторите" }
  if ($LASTEXITCODE -ne 0) { throw "Подпись SHA256SUMS не сошлась с ключом выпуска ($out). Ничего не запущено; удалите SHA256SUMS и SHA256SUMS.sig из папки и повторите" }
  $m = @(Select-String -LiteralPath SHA256SUMS -Pattern "^([0-9a-f]{64})  (court-gateway-[0-9][0-9A-Za-z.\-]*-windows-$a\.exe)$" -ErrorAction Stop)
  if ($m.Count -ne 1) { throw "В SHA256SUMS не одна сборка для windows-$a, а $($m.Count). Ничего не запущено; напишите нам" }
  $want, $f = $m[0].Matches[0].Groups[1].Value, $m[0].Matches[0].Groups[2].Value
  & $get $f
  if ((Get-FileHash -LiteralPath $f -Algorithm SHA256 -ErrorAction Stop).Hash -ne $want) { throw "Контрольная сумма $f не совпала: файл повреждён или подменён. Ничего не запущено; удалите его из папки и повторите" }
  try { Move-Item -LiteralPath $f -Destination court-gateway.exe -Force -ErrorAction Stop } catch { throw "Не удалось заменить court-gateway.exe ($($_.Exception.Message)). Если служба уже установлена, сначала выполните .\court-gateway.exe uninstall-service. Ничего не запущено" }
  Write-Host "Подпись и сумма сошлись: $f"
  .\court-gateway.exe setup --install-service
  .\court-gateway.exe doctor
}
```

Подпись сверяет `ssh-keygen` из OpenSSH 8.1 или новее. Если команда скажет, что его нет или он
старый (бывает на Windows 10), выполните `winget install Microsoft.OpenSSH.Beta`, откройте
PowerShell от имени администратора заново и повторите команду. На Windows 10 Pro 19045 x64
проверено: встроенного `OpenSSH_for_Windows_9.5` достаточно, ставить ничего не нужно.

Программа спросит логин и пароль Viva и код подключения — больше ничего (адрес хаба и отпечаток его
ключа — только самостоятельно собранная программа). Пароль и код при вводе не отображаются. Затем
она закроет папку от других пользователей компьютера (в ней пароль Viva) и установит службу: та
запускается сама при включении компьютера и перезапускается при сбое.

Журнал службы: `C:\court-gateway\court-gateway.log`.

Если у компьютера нет прямого доступа к GitHub, скачайте на другом компьютере со страницы
<https://github.com/Padelapp-Club/court-gateway/releases/latest> три файла — `SHA256SUMS`,
`SHA256SUMS.sig` и файл, который кончается на `windows-amd64.exe` (на Windows для ARM, например на
процессоре Snapdragon, — `windows-arm64.exe`), — положите их в `C:\court-gateway` под теми же
именами (без `.txt`, который может добавить браузер) и выполните ту же команду: не сумев скачать
файл, она возьмёт его из папки и сверит так же.

### macOS и Linux

Вставьте и выполните целиком, ничего не меняя: команда сама определит систему и процессор
(Linux x86-64 или ARM, например Raspberry Pi 4/5; Mac на Apple Silicon или Intel), скачает в папку
`~/court-gateway` последний выпуск, сверит подпись и сумму и только потом запустит программу.
Скачивает и сверяет она во временной папке, доступной только вам, а в `~/court-gateway` (её команда
тоже закрывает от других пользователей) кладёт только сверенную программу.
`install-service` через `sudo` ставит системную службу: она стартует при включении компьютера (на
Mac — даже если никто не вошёл) и работает от вашего имени. Но если на Mac включён
FileVault, после отключения питания Mac ждёт пароль на экране входа, и шлюз не работает, пока
кто-нибудь не войдёт; чтобы шлюз поднимался сам, FileVault должен быть выключен.

```sh
(
  fail() { printf 'court-gateway: %s\n' "$*" >&2; exit 1; }
  B=https://github.com/Padelapp-Club/court-gateway/releases/latest/download
  D="$HOME/court-gateway"
  case "$(uname -s) $(uname -m)" in
    'Linux x86_64') P=linux-amd64 ;;
    'Linux aarch64' | 'Linux arm64') P=linux-arm64 ;;
    'Darwin arm64') P=darwin-arm64 ;;
    'Darwin x86_64') P=darwin-amd64 ;;
    *) fail "для $(uname -s) $(uname -m) выпуска нет" ;;
  esac
  mkdir -p "$D" && [ ! -L "$D" ] && [ -O "$D" ] && chmod 700 "$D" || fail "папка $D не ваша или это ссылка: переименуйте её и повторите"
  T="$(mktemp -d)" && cd "$T" || fail "не удалось создать временную папку"
  trap 'rm -rf "$T"' EXIT
  curl -fLO "$B/SHA256SUMS" && curl -fLO "$B/SHA256SUMS.sig" || fail "не удалось скачать SHA256SUMS и SHA256SUMS.sig с $B"
  command -v ssh-keygen >/dev/null || fail "нет ssh-keygen: поставьте OpenSSH 8.1 или новее"
  echo 'court-gateway ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIJAe4CDRNNnk++UtmLOdDcQcRc0jK56eYJPo+DfdyK8y' > allowed_signers || fail "не удалось записать ключ выпуска в $T"
  S="$(cat SHA256SUMS)" || fail "не удалось прочитать SHA256SUMS"
  V="$(printf '%s\n' "$S" | ssh-keygen -Y verify -f allowed_signers -I court-gateway -n court-gateway -s SHA256SUMS.sig 2>&1)" || {
    case "$V" in *'illegal option'* | *'unknown option'* | *usage:*) fail "ssh-keygen старше OpenSSH 8.1 и не проверяет подписи: обновите OpenSSH" ;; esac
    fail "подпись SHA256SUMS не сошлась с ключом выпуска ($V); ничего не запущено"
  }
  L="$(printf '%s\n' "$S" | awk 'NF == 2 && $1 ~ /^[0-9a-f]+$/ && length($1) == 64 && $2 ~ /^court-gateway-[0-9][0-9A-Za-z.-]*-'"$P"'$/ { n++; l = $0 } END { if (n == 1) print l }')"
  [ -n "$L" ] || fail "в SHA256SUMS не одна сборка для $P; ничего не запущено"
  F="${L##* }"
  curl -fL -o court-gateway "$B/$F" || fail "не удалось скачать $B/$F"
  printf '%s  court-gateway\n' "${L%% *}" | if command -v sha256sum >/dev/null; then sha256sum -c -; else shasum -a 256 -c -; fi ||
    fail "контрольная сумма $F не совпала: файл повреждён или подменён, ничего не запущено"
  chmod 755 court-gateway && mv -f court-gateway "$D/court-gateway" || fail "не удалось положить программу в $D"
  echo "Подпись и сумма сошлись: $F"
  cd "$D" && ./court-gateway setup && sudo ./court-gateway install-service && ./court-gateway doctor
)
```

Журнал: Linux — `journalctl -u court-gateway -f`, Mac — `~/court-gateway/court-gateway.log`
(до его открытия — `court-gateway.stderr.log`). На Mac запретите сон в настройках энергосбережения;
файл, скачанный браузером, разблокирует `xattr -d com.apple.quarantine court-gateway`; без `sudo`
`install-service` ставит службу пользователя — только для пробы, она работает, пока вы вошли.

### Облачная машина

Создайте самую маленькую машину с Ubuntu (1 vCPU, 512 МБ–1 ГБ). Белый IP и открытые порты не нужны.
Вставьте весь текст [deploy/cloud-init.yaml](deploy/cloud-init.yaml) в поле «Пользовательские
данные» (user data, cloud-init) при создании машины — он скачает программу, сверит подпись и сумму
и поставит. Через 2–3 минуты зайдите на машину по SSH и выполните:

```sh
sudo -u court-gateway /opt/court-gateway/court-gateway setup --config /opt/court-gateway/gateway.yaml &&
  sudo /opt/court-gateway/court-gateway install-service -config /opt/court-gateway/gateway.yaml --run-as court-gateway
```

**Пароль Viva в пользовательские данные не вписывайте:** облако хранит их, и программы на машине
могут их прочитать (почему — в начале [deploy/cloud-init.yaml](deploy/cloud-init.yaml)).

### Docker

**Образ выпуска пока не публикуется:** Docker сейчас — только самосборка из исходников. Такой образ
**не обновляется сам**, и `setup` нужны адрес хаба и отпечаток его ключа. Когда образ выпуска
появится, его дайджест будет в подписанном `SHA256SUMS`, и в `docker-compose.yml` вписывается
`<реестр>/court-gateway@sha256:<дайджест>` оттуда, а не тег. Обновления он будет ставить внутри
контейнера. Папка состояния (счёт отклонённых входов в Viva и проверенные обновления) лежит в томе
`state` из `docker-compose.yml` и переживает пересоздание контейнера (`docker compose up --force-recreate`).

```sh
docker build -t court-gateway:local .
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/config" court-gateway:local setup --config /config/gateway.yaml \
  --hub-url <адрес хаба> --hub-key-fingerprint <отпечаток>
docker compose up -d
docker ps                                  # через минуту статус контейнера — healthy
```

Контейнер не публикует портов. В образе объявлена проверка здоровья
(`/court-gateway healthcheck`): `healthy` — шлюз вошёл в CRM, подключился к хабу и его клубы приняты;
`unhealthy` — нет, код причины виден в `docker inspect` (коды — [docs/hub.md](docs/hub.md#мониторинг)).
Код выхода `healthcheck`: 0 — готов, 1 — работает, но не готов, 2 — служба не запущена или зависла;
`healthcheck --live` отвечает 0, пока служба работает, готова она или нет.
Секреты передаются контейнеру переменными окружения из `.env` (`env_file` в compose), а
`gateway.yaml` монтируется только для чтения.

## Проверка: `court-gateway doctor`

```
court-gateway 0.2.0 (release)
Установка my-net: конфигурация клубов версии 3 (club-north, club-south); служба применила версию 3 и обслуживает: club-north, club-south
[ок  ] CONFIG_VALID      установка с CRM viva; клубы настраиваются на хабе
[ок  ] SECRETS_FILE      .env доступен только владельцу
[ок  ] CRM_LOGIN         по данным службы, проверка 14:05: вход в CRM выполнен
[ок  ] CRM_OCCUPANCY     по данным службы, проверка 14:05: занятость клубов на сегодня читается
[ок  ] HUB_REACHABLE     хаб отвечает, сертификат проверен
[ок  ] HUB_AUTH          хаб узнал шлюз установки my-net
[ок  ] TUNNEL_CONNECTED  служба шлюза на связи с хабом
[ок  ] HUB_CONFIG        конфигурация клубов: версия 3, клубы: club-north, club-south
[ок  ] VERSION_CURRENT   версия 0.2.0 — последняя
Всё в порядке.
```

Пока служба работает, `doctor` сам в Viva не входит, а показывает, что увидела служба при последней
проверке (её время — в строке); без запущенной службы он проверяет вход сам и сразу закрывает сеанс.
Если служба запущена, но свежих данных о её проверке нет, `doctor` пишет «нет свежих данных службы»
и успехом это не считает — повторите его через минуту.

Сразу после установки, пока оператор ещё не подключил клубы, `CRM_OCCUPANCY` пропускается, а
`HUB_CONFIG` пишет, что клубов пока нет, — это нормально, делать ничего не нужно.

У каждой ошибки есть подсказка, что сделать. Код выхода не ноль, если есть ошибка. `doctor --json`
выдаёт то же для программ; секреты не печатаются никогда.

## Что делает `setup`

`setup` проверяет вход в CRM (неверный пароль не тратит код; сеанс проверки он сразу закрывает), сверяет ключ хаба с ключом выпуска
или отпечатком оператора (не совпал — `HUB_KEY_MISMATCH`, ничего не записано) и обменивает код на
постоянный секрет. Он записывает `gateway.yaml` (хаб, установка, ключ хаба, тип CRM и логин; клубов
там нет) и `.env` (пароль Viva и секрет, доступ только владельцу); как шлюз доверяет хабу —
[docs/hub.md](docs/hub.md#как-устроена-связь).

## Лунда: вход сотрудником клуба

У Лунды нет пароля: в неё входит человек. `setup` с `--crm lunda` (или ответом `lunda` на вопрос о
CRM) делает это так же, как админка Лунды:

1. **Вход.** Программа рисует в терминале QR-код (и кладёт его картинкой рядом, если терминал не
   показывает), сотрудник клуба сканирует его в приложении Lunda Padel и подтверждает вход. Второй
   способ — телефон сотрудника и код, который Лунда пришлёт в Telegram или пушем. QR-код живёт около
   минуты — программа сама выпустит новый. Если у сотрудника несколько клубов, программа спросит, какой
   обслуживает этот шлюз. Лучше завести для шлюза отдельного сотрудника с минимальной ролью, а не
   входить личным телефоном администратора: шлюз действует от его имени.
2. **Служебный клиент.** Сразу после входа программа просит найти и выбрать служебного клиента клуба
   (обычно клиент с названием клуба): на него встают брони партнёров. Свой клиент партнёр в Лунде не
   заводит. Пока клиент не выбран, шлюз показывает занятость, но брони не ставит (`setup` предупредит).

**Сессия.** Лунда выдаёт шлюзу сессию, и шлюз продлевает её сам, без человека. Она хранится в папке
состояния шлюза (`state/crm-session`, доступ только владельцу) — как пароль Viva в `.env`, это секрет
входа, а не данные клуба. Отозвать доступ шлюза можно в любой момент в Лунде (завершить сеанс
сотрудника).

**Как выглядит бронь партнёра в Лунде.** Обычная бронь корта на служебного клиента со скидкой 100%:
статус «оплачено», платежей нет, в кассу и отчёт внешних платежей клуба ничего не пишется. В
комментарии брони — пометка `[cg:<партнёр>]` и комментарий партнёра. Шлюз отменяет только такие
брони и только до начала; брони клуба он не трогает никогда.

### Если сессия Лунды закончилась

Если Лунда завершила сессию (сотрудник вышел, его отключили, сеанс отозвали), шлюз перестаёт писать в
Лунду, партнёры не могут бронировать, а мы получаем тревогу (`CRM_AUTH_FAILED`); `doctor` пишет
«сессия CRM закончилась». Код подключения не нужен: в папке шлюза выполните
`court-gateway login` (Windows: `.\court-gateway.exe login` в PowerShell от имени администратора) и
войдите так же, как при установке. Служба подхватит новый вход сама — перезапускать её не нужно.
`set-password` для Лунды не нужен: пароля у неё нет.

В Docker сессия живёт в томе состояния, поэтому входят одноразовым контейнером с этим томом — и
после `setup` (его вход прошёл в одноразовом контейнере, без тома), и когда сессия закончилась:

```sh
docker compose run --rm -it court-gateway login
```

## 1С:Фитнес клуб

Шлюз говорит с 1С клуба через API внешней системы — тот же, через который работают сайт и
приложение клуба. Понадобятся (всё есть в 1С клуба, вендор не нужен):

- **адрес 1С клуба** — «адрес для отправки запросов» из карточки внешней системы, без хвоста
  `/hs/api/v3` (например, `https://1c.example.ru/club`);
- **пользователь 1С** с ролями «Удаленный доступ внешнее приложение» и «Запуск внешнего
  соединения» и **его пароль**;
- **ключ приложения** из карточки внешней системы. Его выдаёт 1С клуба, это ключ клуба. «Секретный
  ключ» из той же карточки шлюзу не нужен;
- **для броней партнёров:** услуга аренды «Аренда корта PadelApp» — цена 0, без основания оплаты,
  шаг 30 минут, на всех кортах — и **технический клиент** в 1С (его телефон), на которого встают
  брони. Без услуги шлюз только показывает занятость.

`setup` с `--crm fitness1c` спросит адрес, пользователя, пароль, ключ приложения, телефон
технического клиента и имя партнёра хаба, чьи брони он ставит (например, `padelapp`). Пароль и ключ
уходят в `.env` (`CRM_PASSWORD`, `FITNESS1C_APIKEY`), остальное — в `gateway.yaml`. На хабе у клуба —
`studio` (id клуба в 1С), у кортов — `fitness1c_room` (id помещения), у услуг —
`services.booking.service` (id услуги «Аренда корта PadelApp»); черновик клуба `discover` собирает
сам.

**Что видит партнёр.** Занято всё, что 1С не показала свободным в сетке аренды с шагом 30 минут, —
в том числе время вне сетки (например, ночь): 1С так и не продаёт его. Брони клуба — отрезками
времени, без имён и услуг. Цена — цена услуги аренды за сеанс в пересчёте на час, одна на весь
день. Часовой пояс — тот, что у клуба в 1С.

**Как выглядит бронь партнёра в 1С.** Аренда корта по услуге «Аренда корта PadelApp» на
технического клиента, цена 0, сразу «Записан» — без оплаты и без чеков. Если 1С вместо брони сделала
временный резерв (у услуги остался признак «требуется основание»), шлюз снимает его и отказывает
партнёру. Отменить бронь через шлюз может только тот партнёр, для которого настроен технический
клиент, и только до начала игры; брони клуба шлюз не трогает никогда. Оплату в 1С шлюз не пишет.
**Технический клиент — только для шлюза.** В 1С у аренды нет комментария, поэтому свою бронь шлюз
узнаёт по клиенту и услуге: всё, что стоит на техническом клиенте по услуге «Аренда корта PadelApp»,
он считает бронью партнёра. Не бронируйте на этого клиента ни на ресепшене, ни из других программ (в
том числе из прежней интеграции PadelApp с вашей 1С) — заведите шлюзу отдельного клиента.

**Если 1С отказала во входе** (сменили пароль, отключили пользователя), шлюз две минуты не ходит в 1С,
чтобы не заблокировать пользователя, и партнёры не могут бронировать (`CRM_AUTH_FAILED`). Новый пароль —
`court-gateway set-password`, как для Viva; новый ключ приложения — строкой `FITNESS1C_APIKEY` в `.env`
и перезапуском службы.

## Одна установка — одна копия шлюза

Запускайте шлюз установки только в одном месте. Вторую копию с тем же секретом (скопированная
папка, второй компьютер) хаб не обслуживает, пока работает первая (`DUPLICATE_GATEWAY`); когда
первая остановилась, вторая начинает работать сама ([подробнее](docs/hub.md#как-устроена-связь)).

## Если сменили пароль Viva

Если Viva отказала шлюзу во входе, он пробует войти снова только трижды — через 15 минут, через час
и через 4 часа — и дальше ждёт `set-password`, чтобы не заблокировать вашу учётную запись (счёт
переживает перезапуск); пока вход не удался, партнёры не могут бронировать, а мы получаем тревогу
(`CRM_AUTH_FAILED`).
Новый код подключения не нужен. В папке шлюза выполните `court-gateway set-password`
(Windows: `.\court-gateway.exe set-password` в PowerShell от имени администратора): программа
спросит новый пароль, проверит вход в Viva и заменит в `.env` только его. Служба подхватит его сама
в течение минуты — перезапускать её не нужно. Видит ли служба Viva, показывает `doctor`: строка
`CRM_LOGIN` с `CRM_AUTH_FAILED` «по данным службы» — повод для `set-password`, даже с прежним паролем.

В Docker пароль меняют одноразовым контейнером с папкой настроек, а контейнер шлюза затем
пересоздают: пароль попадает в контейнер переменной окружения при создании, и
`docker compose restart` оставил бы старый.

```sh
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/config" court-gateway:local set-password --config /config/gateway.yaml
docker compose up -d --force-recreate court-gateway
```

## Если в интернет можно только через прокси

Служба не видит переменных прокси из вашей командной строки. Впишите прокси в `gateway.yaml`
(`hub: { proxy_url: http://прокси:3128, no_proxy: "хост, .домен" }`) или в `.env`
(`HTTPS_PROXY=…`, `NO_PROXY=…`): через него пойдут хаб, CRM и проверка выпусков. Для `setup`
задайте те же `HTTPS_PROXY`/`NO_PROXY` в командной строке. Прокси не должен копить ответ хаба
целиком (буферизация): время хаба шлюз берёт, только если заголовки ответа пришли за 5 секунд, а
целиком ответ приходит лишь через десятки секунд. С таким прокси шлюз сообщает `CLOCK_UNKNOWN` и
брони не принимает — отключите для адреса хаба буферизацию или пустите хаб мимо прокси (`no_proxy`).

## Удалить службу

`sudo ./court-gateway uninstall-service` (Windows: `.\court-gateway.exe uninstall-service` от имени
администратора), затем удалите папку. На macOS команда снимает и системную службу, и службу
пользователя — какая есть.

## Если компьютер выключили или пропал интернет

- Партнёры на это время получают ответ «клуб не на связи» (`503 CLUB_OFFLINE`) и не могут
  бронировать через шлюз. Брони, которые вы заводите в Viva, это не затрагивает.
- Мы получаем уведомление примерно через 3–4 минуты и свяжемся с вами, если это надолго.
- Ничего не теряется: шлюз ничего не хранит. Когда компьютер включат, служба запустится сама и
  через несколько секунд снова будет на связи — делать ничего не нужно.

## Обновления

Выключить автообновление: `update: { enabled: false }` в `gateway.yaml`; самосборка (без ключа
выпусков) не обновляется сама никогда. Как ставятся и откатываются выпуски —
[docs/hub.md](docs/hub.md#выпуски-и-подписи); версию службы показывают `court-gateway version` и `doctor`.

## Собрать самому и сверить с выпуском

Нужен Go той же версии, что указана в выпуске (сейчас 1.26.4). Со страницы выпуска скачайте архив
«Source code», а **вне папки исходников** — `release.pub`, `hub-url.txt` и `hub-key.txt`:

```sh
cd court-gateway-<версия>      # распакованный «Source code»
RELEASE_KEY_FILE=~/Downloads/release.pub DEFAULT_HUB_URL="$(cat ~/Downloads/hub-url.txt)" \
  DEFAULT_HUB_KEY="$(cat ~/Downloads/hub-key.txt)" VERSION=<версия> scripts/build.sh
# шесть бинарников в dist/ и dist/SHA256SUMS — сравните с SHA256SUMS выпуска
```

Сборка воспроизводимая, поэтому суммы должны совпасть. Что вшивается в сборку и чем от выпуска
отличается самосборка — [docs/hub.md](docs/hub.md#выпуски-и-подписи).
